## Implemented contract

[The existing guarded HTTP function](../../packages/backend/src/compat/external-http.ts) now accepts Request objects. Its new branch validates the reported URL before native body handoff, explicitly refuses Request redirect-follow/replay, constructs the effective Request using standard RequestInit merge semantics, then validates the copied native URL as well. The latter prevents a server-side Request subclass/own property from masking an internal private destination; this is API hardening, not an ordinary public tenant exploit claim.

Native Request construction preserves method, headers and stream body without buffering or replay. The outgoing Request uses manual redirects and a per-call composed signal joining effective caller cancellation and a10-second deadline. It needs no AbortSignal.any or global transport mutation. Pre-aborted callers refuse before transport. On successful response headers, cancellation/deadline linkage remains active for the response body; links are removed on first abort. Constructor/transport rejection immediately disposes the links. A returned redirect is refused while retaining its bounded abort link for the unread body; no explicit immediate redirect-body cancel guarantee is claimed.

Existing string/URL transport argument shapes, caller-signal precedence and opt-in redirect behavior are unchanged. Request opt-in following refuses even for GET/HEAD, avoiding a partial replay contract. This does not adopt the existing legacy cross-origin POST/header forwarding behavior as generally safe; that policy remains separate review. No DNS resolution or general host/network isolation guarantee is added.
