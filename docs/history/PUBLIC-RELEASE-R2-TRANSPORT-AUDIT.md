# R2 outbound transport boundary inventory

2026-10-09. Read-only source investigation following [behavior isolation findings](PUBLIC-RELEASE-R2-BEHAVIOR-ISOLATION.md). No production source, dependency, build, ledger, transport configuration or live provider changed. No outbound requests or diagnostic tests were executed during primary's build lock. This inventory establishes missing injection seams; **it does not establish an exploitable SSRF bypass**. A guarded-denial counterexample is still required before that claim.

## Observed chain

[Compat app](../../packages/backend/src/compat/app.ts) selects `deps.externalFetch` or global fetch. [Guarded transport](../../packages/backend/src/compat/external-http.ts) accepts HTTPS only, rejects URL credentials and explicit loopback/private/link-local hostname forms, forces manual redirects, uses a10second timeout when caller has no signal, and validates each opt-in redirect destination. It does not resolve DNS or enforce hostname-to-address policy. Host-specific injected fetch can supply stronger egress controls; that injection must actually reach the driver to apply them.

These observations concern the implemented hostname/transport seam, not a new promise of complete DNS/SSRF protection. Caller signal replaces the timeout signal; a repair should preserve existing behavior deliberately rather than silently changing timeout policy.

### Authorization and secret boundaries

Compat middleware requires authentication and owner context; `/api/edge-*` and `/api/sync/*` also require privileged administrator roles. [SyncStore](../../packages/backend/src/compat/sync-store.ts) owner-scopes datasources and encrypts stored config. Generic edge resources require successful cipher encryption before storing config. These controls are separate from outbound URL validation and must survive any repair.

[Directory preview](../../packages/backend/src/compat/routes/directory-preview.ts), editorial, publication preparation, destination preflight and sync operations build runners from owned datasource records after account hydration. The factory currently cannot take externalFetch, so strengthening only one route leaves the same runner chain elsewhere untouched. [Public data execution](../../packages/backend/src/compat/routes/data-execute.ts) is mounted before blanket authentication for intended published queries; it resolves the request's host/owner and finds the datasource within that owner's list before construction. Source ownership checks are not permission for a visitor to send arbitrary server credentials or destinations. No anonymous policy bypass is asserted from this source trace.

## Installed SDK constraints, checked without network

Inspected local installed packages matching edge-infra manifest: libsql client/core0.17.4 and HRANA0.10.0; PostgREST2.110.2; Neon1.1.0. These are reproducible installed-source observations, not a claim about every SDK release or supported host.

- libsql `Config.fetch` is a per-client HTTP hook. Node and web entry points call `expandConfig(config,true)`: default `libsql://` becomes HTTPS; `?tls=0` with explicit port becomes HTTP. Explicit `ws`/`wss` uses WebSocket transport; local file/memory uses native SQLite in Node and is refused by web entry point. An HTTP hook does not govern those other transports.
- HRANA endpoint discovery invokes `fetch(Request)`; pipeline/cursor requests are **POST Requests carrying headers/body/auth token**. It also adopts a response `baseUrl` for later requests. Policy must validate every actual request destination, including this protocol-level switch; validating only the original configured URL is insufficient.
- Existing backend wrappers often convert a Request to `input.url` and forward only a separate `init`. That loses embedded POST/method/headers/body when an SDK invokes fetch with Request alone. **Do not wire libsql to that wrapper unchanged.** A proper adapter must preserve Request semantics and enforce redirect/destination policy without consuming the body twice.
- PostgrestClient supports per-instance `options.fetch`; current runner omits it. Constructor retains auth headers and request builders pass the chosen transport. This is the smallest available per-instance HTTP seam.
- Neon exposes `neonConfig.fetchFunction` as a global-only setting in installed declarations; `neon()` options include fetchOptions but not a per-query fetch function. Mutating global configuration around a request would race tenants/hosts. Primary must select a stable adapter-level policy or another supported per-instance transport, not temporarily replace a global fetch.
- D1 REST has two direct calls that can accept an explicit per-instance fetch dependency. No new provider API or network call is needed to make them injectable; affected-row response semantics remain a separate adapter gate.

## Evidence classification

The behavior diagnostic already observed calls outside scripted externalFetch, then installed a throwing offline global guard in its final runs. This proves **test injection coverage is incomplete**. This inventory confirms the corresponding source chains. It does not show a protected private destination being reached, secret forwarding to an untrusted endpoint, DNS rebinding, or a production host egress policy being evaded. Those claims remain unproved. SQL activity or HTTP200 `success:false` cannot turn a failed vector round trip into provider acceptance.

## Proposed smallest repair and negative diagnostics

Proposals require primary review; none is an accepted architecture change:

1. Define a Request-preserving guarded HTTP adapter at the backend/infra boundary. Infra accepts an optional transport contract without importing backend policy; backend supplies owner-aware host transport wrapped in the existing destination guard. Keep operator-native file/memory/wire access separately explicit. Do not expand public admin capabilities to make a test pass.
2. Thread per-instance HTTP transport through datasourceRunner to PostgREST, D1 REST and libsql runners, and through libsql vector options. Inventory every factory caller above. Validate normalized SDK HTTP destinations per request; refuse unsupported remote WebSocket/plain HTTP paths on guarded admin paths unless a separate reviewed policy exists. Preserve trusted local self-host vector configuration.
3. Treat Neon/wire transports as separate acceptance tasks. Do not implement transient global fetchFunction replacement, silent raw transport fallback or suppress errors as success.

**Proposed next synthetic diagnostic, not executed:** use invented in-memory state and a recording *throwing* global SDK transport; inject a denied guarded fetch; construct a Turso vector probe with a denied literal private host and a Supabase datasource query with a denied literal private HTTPS host. Record whether the policy refuses before the fallback spy is invoked. The fallback must never perform network. First establish the guard's denial for the same normalized URL independently. Expected RED under current source is evidence of bypassing the injected denial boundary only, not actual private-network reachability. Primary should approve its exact scope and file ownership before execution.

Repair acceptance must then prove: ordinary HTTPS query round trip through the injected transport; POST method/auth/body preservation for Request-only SDK calls; URL credentials and private literals refused before any transport; public-to-private HTTP redirect refused; HRANA response baseUrl changes refused; libsql tls downgrade/query parameters rejected on guarded paths; unsupported WebSocket refusal; existing file/memory env path retained; distinct-owner datasource/account refusal before transport; no credentials in browser/error/log output; opaque errors; accurate D1 affected rows; no fallback to raw/global transport on injected denial; parallel requests cannot change another tenant's transport; supported host bundles and affected functional/mutation/SSRF/no-leak gates. DNS-to-private behavior requires an actual host resolver/egress capability decision and cannot be claimed from string checks.
