## 3. What shipped

### 3.1 Quick-fixes (3.1.1)
Each diagnostic `Issue` now carries an optional **`edit`** — a search-replace a machine can apply directly (the `--json` AgentOutput includes it). `applyEdit` is the reference implementation the gate proves.

| Code | Edit | Machine-applicable? |
|---|---|---|
| `MISSING_SCHEMA` | insert a `Schema` stub at end of file | ✅ (apply → check passes) |
| `FB003` | append `.describe('TODO')` to the property (line-anchored, unique) | ✅ (apply → prop no longer flagged) |
| `UNSUPPORTED_ZOD` | comment out the offending line with a TODO | ✅ (apply → diagnostic gone) |
| `FB001` / `FB002` / `TS####` | descriptive `fix` only | ❌ semantic — `fixable:false` |

**Two real bugs caught while building this** (the tests were wrong, not the code): the FB003 edit's `oldString` matched inside `subtitle:` (anchored to line-start to fix), and `.describe('')` is falsy so the rule still flagged it (changed to `.describe('TODO')`).

### 3.2 `check --parity` (3.1.2)
`runParityCheck(manifest)` renders each page through `direct`/`proxy`/`draft` (reusing the `simulate` harness — one code path) and reports a `PARITY_DIFF` diagnostic with the divergence offset if any provider's bytes differ. Wired as `frontbase check --parity <manifest>`.

**RULE 8:** the gate is mutation-proven — a provider-sensitive executor (returns different data per provider) makes `--parity` go RED and report the diff. A provider-agnostic page stays GREEN.

### 3.3 Agent templates (3.1.3)
`docs/guides/agent-authoring.md` — four prompt templates (component / page / query / workflow) encoding the conventions, the supported/unsupported Zod surface, and the golden rules, plus a self-check recipe (`frontbase check --json`, apply every `edit`, re-run).

### 3.4 Raised-difficulty success rate (3.1.4)
The deterministic cohort expanded from 5 to **10** with harder shapes: nested arrays-of-objects (`z.array(z.object({ ..., socials: z.object({...}), skills: z.array(z.string()) }))`), nullable fields, format-heavy (`.url()/.email()/.uuid()/.datetime()`), 3-level-deep object nesting, array-of-arrays, and multi-value enums. **18/18 clean (100%)** — the >95% bar holds at raised N and difficulty (the Phase 1 baseline was 100% at N=8; this raises both).

### 3.5 ESLint + dev routing (3.1.5)
- `eslintPlugin` — an ESLint flat-config adapter. **RULE 6:** it does *not* reimplement the rules in ESLint's visitor shape (that would duplicate the logic and drift); it delegates `.lint` to `runLint` — the canonical implementation — so a consumer's ESLint setup and `frontbase lint` produce identical diagnostics. `eslint` is an optional peer dep. A native-visitor ESLint rewrite is a documented follow-up.
- `devPagesFromFs(pagesDir)` — dev-only file-system routing: a `pages/` dir where each `<slug>.json` is a layout and `<slug>.meta.json` carries title/description/queryId. `node:fs`-based (dev-only; never browser-bundled).

## 4. RULE 8 — the new gate is mutation-proven

`check --parity` is the one new security-adjacent gate (a correctness gate). Per RULE 8 it ships with a mutation proof from the start (not retrofitted): `test/parity-check.mjs` breaks a provider's output and confirms `--parity` goes RED with a `PARITY_DIFF`. The quick-fix and dev-router gates are not security gates (no mutation required), but the quick-fix `applyEdit` is tested for uniqueness/ambiguity (it throws on a non-unique `oldString` — the `subtitle:` lesson).

## 6. Known limitations & follow-ups

1. **ESLint native visitors** — the adapter delegates to `runLint` (RULE 6) rather than reimplementing the AST rules in ESLint's shape. A native-visitor rewrite is mechanical but needs the `eslint` dep; tracked as a follow-up for teams who want ESLint-native rule output.
2. **Quick-fix coverage** — three codes (MISSING_SCHEMA, FB003, UNSUPPORTED_ZOD) have machine-applicable edits; the rest are descriptive. `TS####` fixes are generically not automatable (tsc errors vary).
3. **`check --parity` requires a manifest module** (the `--parity <path>` arg), distinct from the project-dir form of plain `check`. Documented in `--help`.
