> A security gate that never goes red is worse than no test — it manufactures confidence. This milestone exists because both Phase 2 audit bugs were green-but-hollow gates. The fix is not "write more tests" — it is "prove every existing test fails when you break what it guards."

---

## 1. What RULE 8 demands, and what shipped

**RULE 8:** every isolation / no-leak / scope / auth gate must ship a mutation proof — break the guarantee it guards and confirm the gate goes **RED**. If you cannot make it go red, the gate tests the wrong thing; fix the gate first, before building features on it.

**What shipped:**
- `scripts/mutation-lib.mjs` — shared harness: `withSourceMutation` (edit the real `.ts`, rebuild, run the gate, always restore), `runGate`, `expectRed`, `expectFired` (for artifact/no-leak exclusions), `summarize`.
- Per-package `test/mutation.mjs` (edge-core, edge-infra, backend, builder, compiler) + a `test:mutation` script in each.
- `pnpm -r test:mutation` at the root — the new integrity gate (run on demand / CI, **not** every commit; it rebuilds under mutation).

**Two mutation kinds:**
- **Source mutation** — edit the package's `.ts` that implements the guarantee (the exact line, located by inspecting the artifact first), `tsc` rebuild, run the real gate, assert non-zero exit, restore in a `finally` (a crash never leaves a package broken).
- **Artifact mutation** (no-leak) — build a *deliberately leaky* artifact (a browser bundle that imports the server module) and confirm the gate's exclusion check **fires** — proving the check is not a no-op.

---

## 2. How to run it

```bash
pnpm -r build                      # baseline (must be green first)
pnpm -r test:mutation              # every security gate must go RED on break
```

Each package's harness first asserts the **baseline is GREEN** (so a red result is genuinely caused by the mutation, not a pre-existing failure), then applies each mutation, rebuilds, runs the gate, and asserts red. A final rebuild restores green. `git status` after a run shows **only intended changes** — no mutated source is left behind.

## 4. Review-fix — the harness found two real problems on its first run

This is the point of RULE 8. The harness did not just confirm green gates; it found two that were **not** real, and they were fixed.

### Finding 1 — backend default-deny "user guard" was HOLLOW (fixed)
The mutation that removed the `!principal.user` guard **stayed green**. Root cause: the authz test's "anonymous" principal (`tenant: undefined`) was constructed by a helper that always set a `user` (`{ id: 'anon' }`). So the `!principal.tenant` guard was the one rejecting — the **user guard was never the thing under test**.

**Fix:** `_helpers.mjs` now accepts an explicit `principal` override; `authz.mjs` adds an isolating case — a principal with a **tenant but no user** (`{ user: null, tenant: 'tenant-X' }`) → 401. Only the user guard catches this, so removing it now (correctly) turns the gate red. Re-run: ✅ RED.

### Finding 2 — a mutation that targeted the WRONG layer (re-targeted)
The mutation "make `toBrowserQueries` include `execute`" was a **no-op** — the gate stayed green. Root cause: `emitBrowserManifest` serializes with `JSON.stringify`, which **structurally cannot preserve functions**. So `toBrowserQueries` omitting `execute` is defense-in-depth, not the load-bearing guarantee — the real guarantee is the serialization boundary. (This is itself a valuable RULE 8 finding: the guarantee is layered, and the load-bearing layer is `JSON.stringify`.)

**Fix:** re-targeted the mutation at `emitBrowserManifest` — mutate it to emit a function (bypassing `JSON.stringify`'s structural protection). The gate now correctly goes red. Re-run: ✅ RED.

## 5. Why this is evidence (and "green" alone is not)

Before this milestone, a passing `scope.mjs` / `authz.mjs` / `sw-no-leak.mjs` was treated as proof the guarantee held. RULE 8 reframes it: **green is necessary, not sufficient.** The sufficient condition is "the gate fails when the guarantee is removed." The mutation harness is now the evidence; the green gate is just the steady state.

Concretely, the two Phase 2 audit bugs are now structurally impossible to recur silently:
- **SEC-P2-1 (page path):** if anyone removes the page-path `enforceScope`, `test:mutation` goes red.
- **SEC-P2-2 (hollow isolation):** isolation runs against a **shared** datastore; dropping the predicate goes red. A future "optimization" that switches back to per-tenant `:memory:` would itself be caught (the mutation would no longer find a predicate to drop in a shared store — the baseline shared-DB assertion enforces realism).

**Appendix — the harness design choices:**
- Mutations edit **source**, not test fixtures, so they catch regressions in the real implementation (a fixture mutation could pass while the source rots).
- Each harness asserts a **green baseline first**, so a red is unambiguously mutation-caused.
- `finally`-restore + a final rebuild guarantee the package is green when the harness exits, even on crash.
- Artifact (no-leak) mutations construct the violation and confirm the exclusion **fires** — the cleanest way to prove a "must not contain X" check is real without editing the check itself.
