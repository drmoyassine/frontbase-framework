# M1.1 — Workflow Engine Extraction Plan

**Status**: Plan (2026-07-07) — the last M1.1 acceptance criterion ("Workflows execute standalone, in-memory mode"). Scoped for a focused follow-up session; not started because it is the most-coupled subsystem and rushing it would threaten edge-core's zero-external-coupling property.

## Source

`services/edge/src/engine/` (~2,430 lines, 14 files) + `schemas/workflow.ts` (types). The AI-agent execution engine: parses a node/edge graph, traverses it (branches, loops, variable mutations), and executes nodes (AI calls, HTTP, MCP, code).

## Couplings to cut (the seams)

The control-flow core is host-agnostic; everything impure is behind one of four provider interfaces. Default = in-memory.

### 1. `WorkflowProvider` (replaces `stateProvider` + `cacheProvider`)
```ts
export interface WorkflowProvider {
    getWorkflow(id: string): Promise<WorkflowData | null>;
    saveCheckpoint(executionId: string, checkpoint: Checkpoint): Promise<void>;
    loadCheckpoint(executionId: string): Promise<Checkpoint | null>;
    clearCheckpoint(executionId: string): Promise<void>;
    updateExecutionStatus(executionId: string, status: ExecutionStatus, nodes: NodeExecution[]): Promise<void>;
    setCooldown(key: string, ms: number): Promise<void>;
    isCoolingDown(key: string): Promise<boolean>;
    deadLetter(executionId: string, reason: string): Promise<void>;
}
export const inMemoryWorkflowProvider: () => WorkflowProvider;   // default
```

### 2. `EventEmitter` (replaces `broadcastExecutionEvent` / websocket)
```ts
export interface WorkflowEvents {
    emit(event: ExecutionEvent): void;
}
export const nullEvents: WorkflowEvents = { emit() {} };          // default
```

### 3. `NodeExecutor` registry (replaces the monolithic `node-executors.ts`)
```ts
export interface NodeExecutor {
    readonly type: string;                       // 'http' | 'code' | 'branch' | 'ai.chat' | 'mcp.call' | ...
    execute(node: WorkflowNode, ctx: ExecutionContext): Promise<NodeExecution>;
}
export interface ExecutorRegistry {
    resolve(nodeType: string): NodeExecutor | undefined;
}
```
- **In edge-core (deterministic, no SDKs)**: `branch`, `setVariable`, `delay`, `http` (Web Fetch), `response`, `loop`.
- **In @frontbase/edge-infra (AI-coupled)**: `ai.chat` (Vercel AI SDK + `@ai-sdk/{openai,google,anthropic}`), `mcp.call` (`@modelcontextprotocol/sdk`), `agents`.
- **Default registry**: edge-core built-ins + a stub that throws `executor_not_registered` for AI/MCP nodes (so in-memory runs cover control flow + HTTP; AI needs edge-infra wired).

### 4. `expr` (Liquid-based expression eval) — vendored as-is (already `liquidjs`-only).

## Test (acceptance)

`test/workflow.mjs`: build a 4-node workflow in-memory — `start → http(GET /api/data/x) → branch(on status) → setVariable/response`. Execute through `executeWorkflow()` with `inMemoryWorkflowProvider` + `nullEvents` + the edge-core executor registry. Assert: traversal order, branch taken, variable mutation recorded, `completed` status, checkpoint saved/loaded. An AI node asserts `executor_not_registered` until edge-infra is wired.

## Size impact

The workflow core adds control-flow + liquid expr + built-in executors. Estimate +15–25 KB gzip — **approaches the 70 KB budget** (currently 57.2 KB). Options if it breaches: (a) tree-shake the workflow runtime out of the browser SW bundle (the SW never executes workflows — only the edge does) via a separate `workflow` subpath export that the SW entry doesn't import; (b) raise the SW-engine budget while keeping the edge-engine budget. **Recommend (a)**: workflows are edge-only, so they must not be in the SW payload at all.
