## Implemented boundary

- A strict server capture contains one configuration revision, owned saved role templates, scoped institution/program/city records and explicit immutable article approvals. Article metadata alone is insufficient: preparation validates the snapshot schema, configuration and content fingerprint. Canonical drafts are never substituted for approved articles.
- First slice: at most 48 records per collection and 1 MiB of serialized UTF-8. Required templates, parent records, duplicate IDs, normalized URL collisions, reserved paths and mutable legacy datasource bindings are refused. City detail/informational-page templates, pathway publishing, full catalog storage and advanced filters are not supported by this capture version.
- Existing compiler stable serialization produces a full SHA-256 artifact identifier. Artifacts are immutable in owner-scoped settings and reads verify integrity. Internal active-pointer storage uses generation/hash compare-and-swap for activation and rollback; this is a tested storage primitive, **not an exposed activation API or a permission to publish unreviewed candidates**.
- Registered snapshot queries retain strict parameters and owner context. The original requested path replaces authoring sample paths. Institution programs and a program's parent institution use captured relationships. Query/body projections use existing components and the same engine.
- Private preparation/JSON preview/HTML rendering require existing authentication and administrator role. HTML previews use the existing engine, no-store and noindex/nofollow; their internal detail links retain the same captured hash. CMS public-host dispatch now uses the reviewed reader and current network-only SW; production cache, complete sitemap/indexing and live activation controls remain pending. Cache identity includes owner, capture, path and normalized parameters; production cache behavior remains unverified.
- Page Settings offers template selection, scoped record lookup, institution/program selection and inclusion of matching approved article revisions. Exact-hash recovery and whole-version review controls are implemented. Preparing does not save the editor's current unsaved layout or publish anything. Candidate history browsing, review revocation and publish/rollback controls remain pending.

## Reviewed activation and public-read boundary

Later captures do not inherit review; stale rollback cannot overwrite a newer generation. The low-level storage primitive remains internal and no HTTP activation endpoint is exposed.

An internal reviewed reader returns explicit inactive, missing, unavailable or resolved states.
