## Scope and shared contracts

- Expose the existing Supabase adapter in the hosted configuration, reuse its Connected Account/project/schema picker and server-only grant references, and admit create/reuse during Review. Review does not provision SQL or bindings.
- Add protected read-only PostgREST connection/schema discovery through the existing provider-resources router, guarded HTTP transport and SQL runner. Keep credentials in memory; invalidate successful discovery when URL/key changes. Select an existing empty dedicated schema or explicitly create a named schema during Apply. System/public schemas are reserved for this new provisioning path; old connect-only manifests remain supported.
- Apply stays behind the existing durable compare-and-swap claim. Supabase uses its Management API to set up only the selected schema; self-hosted PostgREST uses its existing privileged execute_query/execute_sql helpers. Missing SQL capabilities/DDL permission are prerequisites, not silently emulated table REST operations. A failed/unknown write remains uncertain; do not replay DDL or host activation.
- New per-installation query/exec/migration RPC names live in the existing public RPC schema, with fixed application search_path and SECURITY INVOKER. Preserve existing RPC functions and PostgREST exposed-schema configuration. New application tables stay in the selected namespace. Atomically refuse occupied/existing-for-create schemas and claim them with an installation marker under a PostgreSQL advisory lock. Strip PUBLIC and inherited default-role execution grants from the new RPCs before granting the server role.
- The installed app reuses the existing PostgREST runner and profile lowering. Supabase's setup Management API token is removed from the transformed state profile. The runtime API key is a **server-only, potentially project-wide privileged credential**, not a schema-scoped PostgreSQL login; do not claim those permission models are equivalent. Owned management authorization can still remain encrypted in Connected Accounts under the existing separate contract. API keys, cookies and owner links never enter Git, manifests, public responses or screenshots.
- Reuse the existing lexical PostgreSQL scanner for both TCP numbering and HTTP value inlining, including qmark parameters, quoted literals/comments and dollar-quoted bodies. A real database test exposed the missing qmark support in the prior HTTP runner.
- HTTP requests cannot hold a PostgreSQL connection transaction across calls. Add an optional narrow DbRunner migration-plan operation and invoke the existing backend migration list in one invoker RPC under the existing migration lock. No callback-based pretend transaction or process-local migration mutex.
- Disable hosted Review until the form is mounted, and reject review before the required state connection/schema selection is complete. This also addresses the observed early-click undefined snapshot error.
