## Implementation boundary

Homepage, Explore and Blog list elements use ordinary datasource/table/saved-view bindings. Explore retains Institutions Default and the Programs alternative with direct Default inheritance. Legacy listing record mappings become normal Card/@ mappings, retaining IDs, styles and authored controls. Detail pages retain their reviewed route/content artifacts; their content is not silently replaced by mutable editorial drafts.

Native PostgreSQL SELECT views read the current canonical rows without copying their values into a new table. Guards retain the currently approved IDs and paths, country scope and parent relationships. Programs depend on the admitted institution view. Articles require their currently approved revision and original source/role. A changed article revision is excluded until approval/admission is refreshed; this conversion is not a new editorial publishing workflow. New records do not become public merely by appearing in a canonical table. The existing reviewed membership is a saved admission filter, not a frozen copy of datasource records.

Only explicit public list fields enter these views; body/private evidence fields are excluded. URL identity is projected to its existing relative path; source media whitespace and summary bounds retain existing normalization. Views use PostgreSQL15 invoker security. New view access is restricted to the existing server role; no source-table grants, account credentials, RLS policy or auth configuration is changed. Frontbase saved views in Data reference the native views and carry the country filter and visible column configuration.

Publication admission accepts strict authored live saved-view bindings and rejects credentials, executable query configuration and transient seed rows. Live initial records resolve through the existing same-host data API, retaining its tenant/view/SQL guards and original request session. Before exposing the datasource ID, an opt-in server policy restricts non-administrator access to view bindings in the active reviewed publication. Raw table/SQL, joins, unregistered views and table read/write fallbacks are refused for this source. Console administrator inspection remains available; unrelated sources retain their existing behavior. The same component/query path hydrates on the public page. Missing live execution fails closed. Legacy version1 artifacts remain incompatible with live lists; version2 manifests support them.

The authenticated migration prepares source views, checks exact approved populations, creates a layout-only derivative and stores an owner-scoped hashed server plan. Publishing checks the exact plan, all draft state hashes and the active pointer. Draft changes use the existing durable PageChangeStore CAS/recovery path; pending designs are retained, not published. The active candidate uses only the previously reviewed published layouts. Concurrent conflicts stop activation; a partially completed draft conversion retains per-page recovery receipts and must be inspected/reprepared, never blindly replayed. Native view creation/preparation is additive and separate from activation.
