Plan and implementation:

1. Edge-core owns a pure, bounded condition/operand model and evaluator. Rules compare typed literal or scoped-variable operands; groups support AND/OR. No `eval`, `Function`, executable expressions or provider dependencies. Invalid expressions fail closed. Legacy filter `when` objects and ordinary comparison/AND/OR visibility strings remain readable; new visibility conditions use a version-identifiable string payload in the existing layout field. Unsupported saved expressions are preserved and visibly identified until explicitly replaced.
2. One ConditionsEditor and ConditionValueEditor supply both authoring surfaces. Values support text, finite numbers, booleans, null, JSON lists/objects and @ references; exact variable values retain their type. JSON-compatible values are the serializable boundary, not JavaScript functions/classes. SQL/provider operators still determine whether a particular value shape is meaningful. SQL IN uses arrays; null equality maps to null predicates. Existing comma-list filters remain readable.
3. SSR, hydrate visibility, list query hooks and the legacy filter adapter consume the common engine. URL/local/session/cookie conditions remain reactive; server values are resolved from request context. Existing Menus audience restrictions compile to the same comparator, retaining their dedicated validated audience schema/editor.
4. General published conditions receive a minimal host-verified App Users projection using existing provider/contact verification: user ID, Contact Type and Permission Level. No console identity fallback, decoded client claims, credentials or full contacts rows. Public browser context exposes the minimal user fields and referenced page/system/visitor/app/record values; unreferenced private context is excluded. Server-only false visibility removes content rather than hiding it with CSS. Mixed browser conditions remain presentation logic, not access authorization.
5. Verify legacy behavior, typed values, missing variables, invalid/prototype/depth bounds, SSR/browser agreement, real SQLite predicates and existing Menus ownership/audience/no-leak gates. Add independent failure mutations for malformed-condition refusal and private-user projection. Actual browser proof uses disposable synthetic records and identity; a real signed-in staging provider is not claimed without configuration.
