Status: bounded implementation verified locally; source/artifact checkpoint pending. Builds on [reviewed batches](frontbase-translation-reviewed-batches-20261018.md) and the [dispatch plan](frontbase-translation-ai-dispatch-plan-20261017.md). This is native Settings → Translations for selected Default page plain text, not completed multilingual authoring, production generation or deployment.

## Delivered flow

[TranslationBatchForm](../../packages/console/src/components/dashboard/settings/shared/TranslationBatchForm.tsx) follows the existing Settings Card/Button/Label, reference-only fetch, async lock, safe failure and reload patterns. Administrators choose a page and up to four eligible fields, choose a saved target language, and request a server review. The review shows selected text/context, provider account/model, exact request/input/output limits and unknown monetary cost. A fresh unchecked transmission/charge consent controls Approve and start. No load, selection, review, refresh or saved-batch recovery initiates generation.

Preparation and generation require explicit bounded continuation. Progress comes from persisted jobs/status, not a browser timer or local queue. Draft text is escaped React text with automatic direction. Outdated or unreachable storage prevents continuation; cancel remains available. Unknown usage requires a separate explicit count-as-consumed acknowledgment and never defaults to a release/refund. Ambiguous mutation responses clear approval and block retries until status recovery. Leaving the screen schedules nothing. No source bodies, approvals or batch state are written to browser storage.

Saved batches are discoverable and reopenable after reload. A stale planned review cannot be reapproved but its status/cancellation remains accessible. Review recovery rechecks current owned source/settings; old hashes are not treated as authority. Existing storage and AI forms remain, with their no-call settings semantics. The UI reads the actual host capability, rather than assuming the older generation-settings flag enables execution. Saving new settings requires reloading batch controls.

## Server and contract reuse

[Discovery/recovery](../../packages/backend/src/compat/translation-batches.ts) reuses the execution extractor, owned PagesStore and sealed batch records. Page metadata is tenant-scoped and keyset-paged at25; field discovery scans at most100 candidate fields per cursor and returns only execution-eligible plain text; saved metadata is keyset-paged at20. Source layout size/version bounds remain; one parsed layout/hash is reused during field discovery. Saved metadata does not contain source bodies. Arbitrary client source text, owner scope, SQL, provider URL or credentials remain unavailable.

New authenticated GET routes under `/api/project/translation-batches/` are `sources/`, `sources/:pageId/`, `reviews/` and `:id/review/`. All reuse the existing administrator/default-deny/no-store middleware. Cursors are bounded and query values are parameterized. Deleted/foreign pages, invalid cursors, corrupt records and stale review recovery refuse safely. Existing Start/Continue/Cancel rules, allowance, original-destination recovery and HTTP protocol remain authoritative; no new SQL installation or persistence protocol.

[Shared host contracts](../../packages/edge-core/src/localization/batches.ts), exported as `@frontbase/edge-core/localization/batches`, validate UI responses and host review/status/discovery output. They are Frontbase integration contracts; the standalone translation engine has no reverse dependency on them. Selection/limits/plan request schemas now have one definition. No new package or provider client is introduced. Initial UX is Settings, not a claim of a new Builder toolbar or visual locale editor.

The trusted execution gate still defaults false. This slice adds no production/environment wiring, real provider call, selected owner settings, owner database upgrade or deployment. The ability to render an approval button in a synthetic fixture is not real spend authorization. `generationAvailable` remains false in saved AI options.
