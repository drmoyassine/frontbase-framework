## Delivered boundary

Settings → Translations adds Saved view field alongside Page, Menu and direct Live record field. Select an owned content connection and saved view, then an explicit record key and text column. The picker links to the existing Data → Saved Views Inspector to inspect/edit filters. Discovery is tenant/datasource scoped and keyset-paged at25. This is single-record identity selection, not a new bulk row browser, automatic traversal or embedded SQL editor.

The server resolves the current view through SyncStore; the client cannot supply a replacement table, datasource, filters or SQL. Both key and selected text columns must be explicitly visible in the view. The existing guarded Supabase/PostgREST client reads only those two columns. A raw key read checks candidate uniqueness among underlying rows visible to the configured credential (not a database primary-key certification); a second projected read adds the saved membership predicates and checks that key/text agree. Ambiguous keys are refused even if filters would hide a duplicate. No unselected predicate column is returned to the browser or provider.

The [HTTP adapter](../../packages/backend/src/compat/saved-view-http.ts) consumes the existing Data Inspector savedViewFilters AST; it does not introduce a second saved-filter format or SQL-execution RPC. Nested AND/OR, scalar comparisons/in-lists, explicit null checks and case-insensitive string patterns have bounded serialization tests. Values are quoted/escaped as PostgREST literals. Unsupported null/object comparison shapes, null/object in-list entries, literal-star patterns, NUL, excessive groups or encoded predicates over8192 characters refuse selection instead of dropping rules. Inspector LIKE percent/underscore semantics remain. HTTP pattern support depends on the selected column's PostgREST operator types; no cast-to-text fallback is claimed. Compiler limits are128 nodes; the shared parser's existing limits also apply. Legacy SQL-restricted `fb_live_` views require the existing explicit saved-filter conversion marker; this feature performs no conversion or installation.

View definition/configuration and source destination/text join the sealed approval checkpoint. A final owned definition read catches edits during the HTTP lookup. Before dispatch and draft completion, the same extractor rechecks current membership and definition. Translation resource identity remains the underlying connection/table/key/field, so selecting the same field through a view and directly cannot duplicate a batch unit. Changing views does not invent a second translated copy. Old page/raw-table selection codec/hash ordering is retained.

Confirmed loss of membership or mismatched projection is a typed deterministic source invalidation: it denies dispatch or cancels a late draft while settling known model usage. A transport/error response remains an error, not proof of source change; post-dispatch uncertainty retains the reservation until explicit reconciliation. This narrow distinction reuses the authoritative runner/accounting flow. No generic catch converts remote failures into a release/refund. Source text/filters, credentials, membership columns and record keys stay out of model prompts except the selected text and existing safe field context. Resource keys remain durable identity in translation storage.
