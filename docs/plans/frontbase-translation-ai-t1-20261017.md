## Changes and reuse

- [HTTP invocation](../../packages/edge-infra/src/ai-http.ts) uses the existing injected ServiceFetch pattern without a new dependency. The server-only ./ai package export has no native database driver or optional SDK dependency. One request, no hidden retry; bounded UTF-8 input/output, manual redirects, abort/deadline, output token cap, strict plain-text completion/refusal/tool/truncation and usage checks. Missing usage remains unknown, never zero. Errors contain safe classifications only.
- [Workflow executor](../../packages/edge-infra/src/executors/ai.ts) adds configuredAIChatExecutor and an optional resolver argument to the existing fullExecutorRegistry. Configured workflow and translation consume the same invoker. Existing default SDK executor/registry behavior is preserved; its environment-default credentials and optional dependency requirements are not newly certified or silently substituted into translation.
- [Host adapter and settings](../../packages/backend/src/compat/translation-generation.ts) reference existing tenant-owned provider records, use existing encrypted Phase2Store config and resolve secrets afresh for rotation. Metadata/kind/provider/active checks precede decryption. The initial accepted protocol is the existing OpenAI connection type on its canonical HTTPS origin; custom base URLs cannot redirect those credentials. Other types remain explicitly unavailable, not a product-level vendor exclusivity decision. No global credential fallback or extra credential store.
- [Configuration routes](../../packages/backend/src/compat/routes/translation-generation.ts): GET/PUT /api/project/translation-generation/ behind default-deny/admin auth, no-store, metadata-only options, bounded4096-byte strict request schema and exact conditional settings CAS. Configuration saves/clear perform no outbound request; there is no generation/start or billable probe endpoint. generationAvailable is false until T2/T3 exist. Existing334-operation community contract remains unchanged by this additive surface.
- [Console](../../packages/console/src/components/dashboard/settings/shared/TranslationGenerationForm.tsx): Settings → Translations adds an existing-account selector, explicit model ID, source/target language codes and output token ceiling. Uses the storage form's save/reload/conflict/error conventions, with no inline secret input. Unsupported/missing accounts stay disabled/preserved; ambiguous saves retain edits and require reload. The output ceiling is clearly distinguished from a spending allowance. No model is auto-selected, discovered or certified by saving. Generation and language publication remain unavailable.
- Generic provider port/context/lifecycle remain in the standalone translation package. Strict shared generation schemas canonicalize languages, reject source-equal/duplicate targets and forbid client-supplied credentials/tenant/URL. Internal adapter only supports plain text and the pinned plain-v1 prompt, includes selected context, refuses source-tenant/locale/prompt mismatch and validates placeholder preservation again after the response. No claim that prompts eliminate injection or replace validation. Provider failures are terminal safe classifications in this initial adapter; ambiguous retry/charge reconciliation remains T2 work. Provider idempotency keys are not advertised as external exactly-once charging.

Protocol reference: [official Chat Completions contract](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), inspected2026-10-17 for max_completion_tokens, non-streamed completion/usage and finish reasons. No model pricing or universal model support inferred; no runtime library selection was changed.
