# Single-binding conditional hidden filters

Status: deployed on isolated staging; single-binding browser behavior verified.

Owner limits this step to one table or existing data view bound to a List Component. No multiple-dataset selector, saved-view creation/snapshot service, Card-default redesign or Explore migration is included. The existing specialized captured Explore binding remains intact. General saved-view adapters will need separate delivery evidence.

In the existing properties panel, Options → Hidden Filters now offers **Apply only when** on each filter. Select an arbitrary existing URL/local variable, Equals/Does not equal/Has a value/Has no value, and an optional comparison value. For example, apply `kind = program` only when `{{ url.type }}` equals `program`. Another condition can target `institution`. Active predicates combine with AND; unconditional filters remain active. Missing/empty variables do not satisfy either equality operator. Scalar zero/false remain valid values; malformed references and prototype paths fail closed.

Existing Set Variable button actions drive these filters. Public URL writes preserve other parameters/hash and use browser history; Back/Forward re-evaluate the query. Builder canvas URL actions simulate visitor state without navigating the editor. Local-state updates use the existing VariableStore. Shared resolution is used by ordinary Repeater/Grid/DataTable, legacy simple-data hooks and the Chart/KPI hook that shares the editor. SSR keeps resolved static/user values and defers URL/local conditions for reactive browser resolution. Query cache keys include active resolved filters, and unfiltered initial records cannot masquerade as filtered results.

Actual browser testing exposed three additional blockers: duplicate React/query contexts in the published bundle, noncanonical builder data URLs reaching a compatibility handler, and unfulfilled normal list-RPC bodies on SQL datasources. Hydrate now deduplicates React/ReactDOM/TanStack Query; builder reads use the canonical trailing-slash route; the existing validated RPC contract has a bounded single-table SQL adapter. It validates projections and sorting against the datasource schema, parameterizes values/paging, computes filtered totals and refuses joins. Existing datasource ownership and Supabase credential policy remain unchanged. Hidden filters are presentation/query scope, never a substitute for access policies.

The legacy table-data endpoint also ignored filters before this repair. It now reuses schema-validated predicates, bounded pagination and filtered counts, without restoring any framework control-database fallback.
