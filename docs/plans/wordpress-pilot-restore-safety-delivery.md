## Implemented contract

`restore` still requires `--confirm-fresh-target`. It now requires an **absent destination and an existing plain parent directory**; even an existing empty directory is refused and preserved. It does not overwrite a running deployment. Source and destination trees must be disjoint. Source/target ancestors are checked with lstat and realpath; symbolic links and Windows junction/alias paths are refused. Source hardlinks are refused. The operator must quiesce the source and prevent concurrent edits to parent directories during this offline rehearsal; the tool does not promise protection against a hostile process racing filesystem operations.

Before creating staging, the tool validates the exact v1 synthetic manifest shape and required fields, portable object keys, case-insensitive duplicates/parent conflicts, reserved database names, file sizes/hashes, SQLite integrity and table inventory. Snapshot filename is fixed; unmanifested journal/WAL/SHM sidecars are refused. Bounds: manifest64KiB, file64MiB, aggregate128MiB, objects2048, tables512. The format remains intentionally restricted to this synthetic fixture, not arbitrary S3 keys or large production datasets. Verification shares this preflight. SQLite read-only opens no longer fall back to a writable open. SQL table identifiers are escaped.

The complete restore is assembled in a fresh `.frontbase-restore-*` sibling created by mkdtemp, using exclusive file writes and restrictive POSIX modes. Sources are checked again during copying; staged sizes/hashes and SQLite integrity/inventory are checked before rename. A final destination check refuses an intervening target. A same-filesystem rename exposes the complete directory. The offline no-concurrent-parent-edit requirement remains essential: portable Node rename is not a cross-platform atomic no-replace primitive.

On stage/write/rename failure, only the exact generated sibling may be removed, after checking its parent/containment and plain-path status. Existing destinations are never cleaned up. If safe staging cleanup cannot be completed, the tool returns `restore-failed-cleanup-required` for operator attention rather than deleting through an alias. A process/OS crash may leave private staging behind; crash durability/fsync and unattended recovery are not claimed. Snapshot files remain sensitive: restrictive file modes are not encryption, and Windows access is governed by directory ACLs.
