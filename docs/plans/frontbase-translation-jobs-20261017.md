## Implemented engine behavior

- [Context contracts](../../packages/translation/src/contracts.ts) and [fingerprints](../../packages/translation/src/identity.ts) bound selected role, label, guidance, neighboring text and locale-specific glossary terms. Unknown fields refuse. Source text and context have separate fingerprints. Context changes advance the registered source version even if wording is unchanged; omitted context preserves authored hints and explicit `{version:1}` clears them.
- [Revision/persistence layer](../../packages/translation/src/revisions.ts) retains immutable registered source/context versions through `readSourceVersion`. Target revisions/intents include context fingerprints (empty-context default for earlier callers). `writeJobResult` requires a persisted job fence; ordinary generated/manual/imported writes are trusted host APIs, not alternatives for completing jobs. The low-level persistence port now requires source-history reads. These APIs remain unpublished/pre-stable.
- [Job contracts and runner](../../packages/translation/src/jobs.ts) process one unit/locale per immutable intent, binding source version/fingerprints, expected head, provider/prompt references, revision ID and bounded attempts. The host supplies a provider and a mandatory authorization callback; no default provider, credential lookup, network call, environment access, autonomous scheduler or paid request exists.
- Host policy authorizes selected-content transmission and any budget reservation. The adapter checks current source/context/head again before recording dispatch. Provider input references immutable, scoped, validated input history and receives a stable tenant/project/job idempotency key and AbortSignal. Plain-message validation/protected tokens apply before a generated result can commit; ICU/MF2 and native rich-text generation remain unimplemented.
- Persisted ready-ID discovery, queued/leased/completed/failed/cancelled state, monotonic lease epochs, trusted adapter clock, renewal, retry/backoff/attempt ceilings, timeouts and conservative uncertain-dispatch counts support restart/reclaim. Stale epochs cannot renew, fail or complete another worker's lease. Lease epochs are concurrency fences, not authentication credentials. A host scheduler must enumerate scopes/ready IDs and invoke bounded `runOnce`; JS timers are provider timeouts only.
- Provider exceptions/responses never enter error fields. Persist only fixed classifications; unknown result fields refuse. Failed or invalid results cannot mutate layout/actions/URLs, activate a locale or publish content.

## SQLite reference implementation

[Base adapter](../../packages/translation/src/adapters/sqlite.ts) transactionally migrates source schema1 to2, adding context columns and immutable source history. Only the known current legacy version can be backfilled; missing earlier wording remains unknown. New current/source-history writes are atomic. This is translation-input provenance for selected fields, not a frozen datasource feature; live source tables/bindings are unchanged.

[Job adapter](../../packages/translation/src/adapters/sqlite-jobs.ts), exposed through `/adapters/sqlite-jobs`, separately initializes job schema1 after the base schema. Partial initialization can be retried; it does not claim one transaction across both schema components. Job foreign keys bind owner/project/unit/source version. Unique job IDs and target revision references are scoped. Bounded ready discovery currently requires SQLite JSON aggregation. No SQL driver or provider SDK is imported; an application injects a dedicated synchronous connection. Async D1/Turso/remote PostgreSQL are separate adapters and proofs.

The target revision append, head/unit-counter update and completed job state share the same SQLite transaction. Both before and after writing the revision, the job adapter checks current lease status/epoch/expiry using its clock. Cancellation and replacement workers fence late output. If completion persistence fails, the revision/head and completed state all roll back. The base adapter refuses job-fenced writes without the job-capable adapter; it cannot silently downgrade completion.

No external API/database provisioning or production schema mutation occurred. Tests use temporary files and in-memory databases. Local v1 migration is additive, preserves existing source/target data and does not fabricate absent history. No new dependencies or lockfile changes were needed.

## Deliberate remaining limits

A provider may finish or charge after timeout/cancellation, and a crash between dispatch and storing its result may require another call. Stable idempotency keys help only if the provider honors them. `uncertainAttempts` conservatively tracks dispatched attempts without a committed outcome; it is neither an invoice nor an immutable per-attempt/budget ledger. Provider usage can be returned but is not yet persisted/accounted. Full reservation/refund/uncertain-charge accounting and configured-provider conformance are required before claiming the paid-AI workflow.

Only registered input changes are fenced; upstream changes not yet observed by extraction cannot be detected. Repeater/page/menu extraction, live-source change detection, memory matching/reuse, glossary management UI, native rich-text integration, actor/audit details, retention/tombstones/export, publication/releases, localized query semantics/SEO/RTL and real contact authorization remain open. Prompt versions are immutable intent references, not a complete stored prompt/model configuration archive. Host adapters must enforce actual authorization/safe transport and use the fenced job completion protocol. No process scheduler or external worker service was provisioned.
