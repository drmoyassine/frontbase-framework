## Outcome and two finish lines

An owner installs Frontbase, connects their database and storage, installs an education-directory template, configures it in `/frontbase-admin`, and publishes under their domain without editing framework source. USA proves migration; a separate country deployment proves reuse. One self-host deployment is one site/application with its own engine/worker, state and domain. Cloud isolation remains relevant without making multi-site self-hosting a requirement.

**Pilot finished:** USA is running on the intended host with reviewed original URLs/content, complete browsing and details, editorial pages, working contacts/inquiries, SEO, media, cache and tested recovery. A second country can install/configure/publish the same template without source edits. Final core/template classification is reviewed and production cutover is authorized and monitored.

**Framework release finished:** the accepted **Frontbase Framework Developer Preview** satisfies its own R1–R4 package, clean-install, security, operations, documentation and release gates. Pilot success does not certify package release; a Developer Preview release does not certify USA migration. [Release strategy](../history/PUBLIC-RELEASE-STRATEGY.md) governs that separate track. GA, universal provider/host parity and CF-22 resumption are not part of this plan.

## Fixed requirements

- Keep six framework packages, existing admin, compiler/query/provider contracts and one renderer/engine. Do not create a second education-specific admin or runtime.
- `public.institutions`, `public.programs`, `public.cities` and `public.countries` remain canonical Studygram data. Supabase's reviewed current content wins; WordPress preserves original public URL identity and supplies missing-record evidence. Editorial uses the existing consumer draft/evidence model; no duplicate institution/program collections.
- Institution → many programs; institution → one city; city → many institutions; city/country links must be valid. Preserve old aliases independently of regenerated names/slugs. Do not infer private provider agreements from public WordPress posts.
- More Supabase records than WordPress is intentional expansion. An original public WordPress record or URL without a reviewed destination/disposition is a migration gap.
- Media lives in administrator-connected storage. Empty optional covers render text-only. Missing-cover enrichment is a separate pass; broken URLs, wrong MIME, unsafe files and missing inline/download assets still require review.
- All domains, country scope, mappings, routes, branding, filters, cards, detail layouts, editorial and CTAs must be configurable. No USA-specific IDs, recipients or secrets in reusable framework code or exported templates.
- Approved content, draft content, list eligibility and indexing are separate states. Installation does not import canonical data, approve content or publish.
