# Frontend text editing

Owner-authorized implementation, preceding the concrete release-gap repairs. Text only: a privileged frontend session stages multiple edits in browser memory, supports per-field revert and global cancel, then commits one compare-and-set copy revision with Save Changes. No write occurs on an individual field's Done button. Failed/conflicting saves retain the local edits.

Reuse the engine's display-field inventory, Block Version identities, shared menu identities and record-key identities. Where a page already has its own published locale release, use its existing manual translation lifecycle and configured translation datasource, then activate one immutable release through the existing CAS. Preserve untouched published revision IDs; never promote unrelated draft heads. A provider failure can leave private drafts, but cannot partially replace the visible release. The same review/history surface must show the saved manual translation.

Source-language copy and page-language surfaces without their own locale release use a Frontbase editorial copy revision, not a write to a connected business table or an alteration to a binding. Keep each language independent. Match the original field fingerprint before applying an override so source drift cannot silently apply old copy to a new source. Persist immutable revision receipts plus one tenant-scoped activation pointer using existing settings/SQL adapters; publication data and original records remain recoverable. Builder projections use the same copy resolver, and responses identify the applied copy revision. Do not bypass immutable site/translation validation or turn unavailable localized pages into source fallback. The authoring source page ID travels from the exact captured resolver result, avoiding a second manifest read or a cross-version lookup race.

Expose the editor only after the normal authenticated, tenant-scoped privileged-role check. Inventory and mutations are private/no-store, bounded and same-origin; field identities are reconstructed on the server, never trusted from arbitrary browser paths. Text must remain plain and cannot alter markup, URLs, actions, placeholders or identifiers. Anonymous visitors receive rendered copy without editor controls or private source metadata. Staging saves are page-batch atomic at the active-pointer CAS; concurrent saves visibly conflict.

Acceptance: English/Arabic and another configured locale, multiple edits, individual/global cancellation, re-editing, save/reload, anonymous delivery, keyboard/RTL/mobile, stale tabs, source drift, tenant/role denial, CSRF, injection and ambiguous-save recovery. Verify the actual host as well as isolated contracts. Live-data translation completeness remains out of scope.
