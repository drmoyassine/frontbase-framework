# Repeater preview and publication parity

Status: deployed on isolated staging; browser comparison verified.

The Explore canvas previously rendered connected canonical records while publication used the reviewed immutable catalog. Its browsing container rendered a placeholder instead of the public controls. These two paths caused different records, images and controls despite sharing the HTML renderer.

The canvas now requests the active captured catalog, pins its hash across query requests, rejects stale revisions/capture changes and prunes the inactive institution/program listing. A new project without an active capture can still preview its connected data. Captured previews remain owner/admin authenticated, tenant scoped and subject to existing chunk/editorial integrity checks. They do not approve or publish content.

Registered directory Repeaters expose visitor tabs, search, pagination, record counts, ordering and title matching. Default records per page, A–Z/Z–A ordering, contains/starts-with/exact-title matching, numbered/Previous–Next pagination and top/bottom/both placement are saved in the layout. Existing standalone browsing controls are inherited when a Repeater first takes ownership and suppressed during projection to prevent duplication. Both views use the same record projection and native browsing renderer. Page size remains bounded by the capture's configured maximum; no unbounded datasource queries are introduced.

DataTable patterns retained: separate display toggles from query configuration, validate page-size inputs, restrict sort/filter fields to supported capabilities and keep parameter values outside SQL text. Avoided: a second presentation implementation or exposing unsupported field selectors. Arbitrary mapped-field facets and multi-field sorts are not implemented by this change: the current immutable index supports title/identity/parent metadata. This receipt must not be read as general arbitrary-field filter support for every Repeater datasource.
