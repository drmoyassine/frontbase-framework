## Implemented locally

- `packages/edge-core/src/localization/contracts.ts`: version1 language/storage config, stable component/record/system refs, typed composite keys, message units, draft revision/release-ref contracts and narrow MessageResolver seam. Same/separate storage uses the same datasource reference shape. Source locale must be enabled; canonical locale duplicates, reserved property names, unknown credential fields and unsafe namespaces refuse.
- `identity.ts`: canonical typed resource identity scoped by tenant/project, composite-key order invariance and independent source/segmenter/token fingerprint. Identity does not change when source wording changes; different owners/projects/connections/typed record IDs do not collide in the fixtures.
- `sitemap-comparison.ts`: no network I/O. Compare sets for each explicit site/locale; retain original literals separately from comparison keys, handle bare-homepage/prefix and subdomain forms, record prefix-only candidates, retain untranslated/translated unmatched paths and accept only explicitly supplied verified mappings. Reject foreign origins, ambiguous normalized literals, conflicting pairs and invalid prefixes/schemes/credentials/fragments. An empty inventory is not an all-clear. No positional alignment, automatic slug translation or Google index claim. `readyForRouteImport` is a readiness result, not authorization; callers must validate evidence against an owner-scoped migration plan before import.
- `rich-text.ts`: bounded interchange tree, stable text segments, Arabic text-only reassembly, original structure/IDs/links preserved, complete patches required, protected {{record.field}} references, forbidden script tags, unsafe links, unknown attributes, oversized/deep/cyclic/duplicate trees and patch refusals. Existing editor formats still need explicit adapters; this is not native published HTML integration.
- `@frontbase/edge-core/localization` export plus dedicated `test:localization`; functional/mutation tests join normal edge-core scripts. Additive changes to an already dirty package manifest preserve unrelated edits; no index cleanup/staging/reset.

All five paths pass hostile interpolation through the existing Frontbase native Text renderer. Output escapes markup; this is text-only integration, not full rich-text/editor/HTML-shell acceptance. Formatter/native catalog/fallback behavior comes from the host fixture, as identified in results.
